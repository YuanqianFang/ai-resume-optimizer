# AI简历优化助手 PRD

## 1. 文档信息

- 产品名称：AI简历优化助手
- 文档版本：v1.0
- 文档日期：2026-04-17
- 文档类型：开发执行版 PRD
- 目标：定义一个面向应届生求职者的 Web MVP，支持上传 PDF 简历、粘贴岗位描述（JD），调用低成本 AI API 完成简历分析、优化建议生成、完整简历重写与 PDF 导出，并可部署后通过链接直接访问。

## 2. 产品背景

应届生在投递简历时普遍存在以下问题：

- 不知道岗位 JD 看重什么关键词和能力点。
- 简历内容过于平铺直叙，缺少量化表达和成果导向。
- 简历与目标岗位不匹配，ATS 通过率低。
- 缺少结构化修改建议，不知道该从哪里改起。

本产品通过 AI 自动完成“简历解析 + 岗位理解 + 匹配分析 + 内容优化 + 导出交付”，降低应届生修改简历的门槛，提高投递质量。

## 3. 产品目标

### 3.1 用户目标

- 让应届生在 3 到 5 分钟内拿到一份更贴合目标岗位的优化简历内容。
- 让用户明确知道当前简历的弱项、缺失关键词和优化方向。
- 支持直接复制结果或导出 PDF，方便快速投递。

### 3.2 业务目标

- 先完成一个无需登录即可直接使用的 MVP。
- 通过低成本 API 验证产品价值和使用链路。
- 支持部署到 Vercel 等免费平台，形成可分享访问链接。

### 3.3 成功指标

- 首次使用用户从上传到拿到结果的流程完成率 >= 70%。
- 单次处理成功率 >= 95%。
- 单次 AI 成本可控，目标平均每次调用成本低于可接受阈值。
- 导出 PDF 成功率 >= 95%。

## 4. 目标用户

## 6. 核心用户流程

### 6.1 主流程

1. 用户进入首页。
2. 上传 PDF 简历。
3. 粘贴目标岗位 JD。
4. 点击“开始优化”。
5. 系统完成 PDF 文本提取与内容清洗。
6. 系统将“简历内容 + JD + 任务提示词”发送给 AI。
7. AI 返回结构化结果：
   - ATS 匹配评分
   - 关键词缺失项
   - 简历问题诊断
   - 分模块优化建议
   - 项目经历优化示例
   - 面试建议
   - 完整优化版简历
8. 前端展示分析结果和优化后简历。
9. 用户可复制文本或导出 PDF。

### 6.2 异常流程

- PDF 解析失败：提示用户上传可复制文本的 PDF，或重新上传。
- JD 为空：禁止提交，并提示必须填写岗位描述。
- AI 返回格式异常：后端重试一次；仍失败则返回友好提示。
- 导出 PDF 失败：保留页面结果，并允许用户复制文本作为兜底。

## 7. 用户价值设计

### 7.1 用户最终获得的内容

- 一个直观的岗位匹配评分
- 一个明确的缺失关键词列表
- 一组可执行的简历修改建议
- 一版针对目标岗位重写后的完整简历文本
- 一份可导出的 PDF 结果

### 7.2 输出原则

- 避免空泛评价，必须给出修改理由
- 优化内容必须尽量贴近应届生真实表达，不夸大履历
- 对不确定的信息用建议表达，不虚构公司/项目成果
- 输出结构适合直接复制到简历编辑器中

## 12. 技术方案建议

## 12.1 推荐技术栈

- 前端：Next.js
- UI：Tailwind CSS
- 后端：Next.js Route Handlers / Server Actions
- PDF 解析：`pdf-parse` 或同类库
- AI 调用：兼容 OpenAI 格式的低成本模型 API
- PDF 导出：`@react-pdf/renderer` 或 HTML 转 PDF 方案
- 部署：Vercel

### 选择原因

- Next.js 适合快速完成前后端一体化 Web MVP
- Vercel 部署简单，适合生成可直接访问链接
- Server 侧调用 API 更容易保护密钥
- Tailwind 有助于快速搭建页面

## 12.2 系统架构

1. 前端上传 PDF 并输入 JD
2. 前端调用后端接口 `/api/optimize-resume`
3. 后端解析 PDF 文本
4. 后端拼装 Prompt 并请求 AI API
5. 后端校验并清洗返回 JSON
6. 前端渲染结果
7. 用户可调用 `/api/export-pdf` 导出 PDF

## 12.3 API Key 放置要求

### 原则

- API Key 只能放在服务端环境变量
- 绝对不能暴露在前端代码中
- 不允许写死在仓库里

### 建议配置

- 本地开发：`.env.local`
- 线上部署：Vercel Project Settings 的 Environment Variables

### 变量命名建议

- `AI_API_BASE_URL`
- `AI_API_KEY`
- `AI_MODEL_NAME`

## 13. 接口定义草案

## 13.1 分析与优化接口

### 路径

- `POST /api/optimize-resume`

### 请求方式

- `multipart/form-data`

### 请求参数

- `resumeFile`: PDF 文件
- `jobDescription`: string

### 响应示例

```json
{
  "success": true,
  "data": {
    "atsScore": 78,

    "issues": ["成果表达不足"],
    "rewriteSuggestions": [],
    "projectRewriteExamples": [],
    "structureDiagnosis": [],
    "interviewTips": [],

  }
```

### 请求参数

### 响应

- `application/pdf`

## 19. 风险与应对

### 风险 1：扫描版 PDF 无法解析

- 应对：明确提示当前仅支持文本型 PDF

### 风险 2：AI 虚构内容

- 应对：提示词中强约束不可虚构，并在结果页提示用户自行核对

### 风险 3：低成本模型输出不稳定

- 应对：使用 JSON Schema 校验 + 自动重试 + 输出兜底

### 风险 4：免费部署存在性能限制

- 应对：MVP 优先控制文件大小、超时和调用次数

用户上传一份 PDF 简历，粘贴一个岗位 JD，系统在一次请求内返回分析结果和优化版完整简历，用户可以复制文本或导出 PDF，这个闭环跑通即视为 MVP 完成。
